Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm is a formula that interpolates between control points to generate points that on a curve that connects the start and end points. Based on a distance t in [0,1], we use the formula \( (1-t)(p_1) + (t)(p_2) \) between all adjacent control points \(p_1\) and \(p_2\) and return the list of resulting sums as the intermediate points. This method is used and repeated until only one sum remains, which is the resulting point that lies on the bezier curve at parameter t, where t=0 indicates the starting point and t=1 indicates the ending point.

Part 2: Bezier surfaces with separable 1D de Casteljau

Similarly, evaluating a Bézier surface follows the same principle as evaluating a Bézier curve, except that it uses two parameters, \(u\) and \(v\), to specify a point across the two dimensions of the surface. We first evaluate the Bézier curve along each row of 3D control points using the parameter \(u\). At each step, we interpolate between adjacent control points \(p_1\) and \(p_2\) using the formula \((1-u)p_1 + up_2\), repeating this process until each row produces a single 3D point. We then use the parameter \(v\) to evaluate the Bézier curve through the resulting points, interpolating until only one point remains. The final 3D point lies on the Bézier surface at parameters \((u,v)\).

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To calculate the unit normal at a vertex, we compute the area-weighted average of the normals of the faces incident to that vertex, then normalize the resulting vector. I adapted the traversal in the printNeighbors() method to iterate through the faces adjacent to the vertex. For each face, I retrieve the other two vertices, \(v_1\) and \(v_2\), and compute the cross product of their position vectors relative to the current vertex: cross((v1 − this->position),(v2−this->position)) Which results in a vector perpendicular to the face with a magnitude proportional to twice the triangle's area. After adding all cross products across all incident faces, I normalize the sum using unit() to obtain the vertex's unit normal.

Part 6: Loop subdivision for mesh upsampling

I implemented Loop subdivision following the procedure described in the assignment. First, I set isNew to false for all existing edges to distinguish the original edges from edges created during subdivision. I then iterated through the vertices using verticesBegin() and verticesEnd(), traversing each vertex's neighbors and accumulating their positions in neighborSum while counting the number of neighbors n. I calculated each vertex's updated position using the formula (1 - n * u) * A->position + u * neighborSum, where u=3/16 when n = 3 and u=3/(8n) otherwise. Next, I iterated through the original edges and calculated each edge's new vertex position using (3.0 / 8.0) * (A->position + B->position) + (1.0 / 8.0) * (C->position + D->position), where A and B are the edge's endpoints and C and D are the opposite vertices of its adjacent triangles. After calculating and storing all new positions, I split each original edge using splitEdge(), then flipped the newly created edges connecting an old vertex to a new vertex when appropriate. Finally, I updated the vertex positions using their stored newPosition values.

After several iterations of Loop subdivision, the cube becomes progressively smoother, with its sharp corners becoming rounded and its edges losing their original sharp appearance. This occurs because subdivision moves vertices toward weighted averages of their neighboring positions. This can be mitigated by pre-splitting edges, which help retain more of the cube's original shape by introducing additional vertices and changing how the geometry is subdivided. The cube can become slightly asymmetric after repeated subdivision, which is caused by the triangulation of its faces. The diagonals chosen when representing each square face as triangles influence the neighborhood relationships and subsequent subdivision geometry. If these diagonals are oriented inconsistently across the cube, subdivision can treat geometrically equivalent regions differently, producing asymmetry. To mitigate this, I preprocessed the cube by splitting selected edges and flipping edges to create a more symmetric and consistent triangulation across its faces. This makes the mesh's local connectivity more uniform, helping subdivision produce a more symmetric result.
